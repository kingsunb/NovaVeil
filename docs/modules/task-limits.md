# 后台任务与限流（internal/task · keylimit）

task 承担后台周期任务，keylimit / channellimit 承担并发与速率两层限流。

## 怎么做的

### 模型自动同步（task）

- `SyncModelsTask` 周期拉取上游 `/v1/models` 重建 auto 模型。
- **双防御防清库**：fetch 层解码前校验 2xx（401/403/429 的错误体不再被误读成"空列表"）；sync 层拿到空列表且渠道已有 auto 模型时跳过删除。任何一层都可能独立挡住"上游瞬时故障清空模型及其分组引用、评估排名"的历史事故。
- 停机 `StopAll` 条件取消 + runningStopped 守卫。

### 并发槽（keylimit）

- 渠道级最大并发用信号量槽位控制，等待走 ctx / stopCh 双路 select；release 用 `sync.Once` 幂等，重复归还无副作用。

### 单 Key RPM（channellimit）

- 滑动窗口按"每 Key 每渠道"计数，锁内清理滑出窗口的条目；时间源用 `time.Time`（带单调钟），系统时钟回拨不影响排序。
- **降额不换容器**：动态调小限额时收缩现有容器而不是重建，防止并发瞬间绕过。

### 管理令牌桶

- 管理 API 令牌桶限速已实现，默认关闭，可按配置开启。

## 设计想法

- **限流的可用性优先于精确性**：RPM 等待期间客户端断开或管理端终止都以取消终态定稿，不发起上游请求；413 / 预算拒绝不进熔断、不记成员失败——限流惩罚的是请求方，不是渠道成员。
- **幂等归还**：槽位 / 预算 / 探测占用这类"必须归还"的资源全部做成幂等，panic 与重复清理都不产生二次伤害。
- **同步空列表保护是产品语义不是防御式编程**：上游返回空可能是真删光了模型，但删除是不可逆的——"宁可少删一次，不可错删一批"。

## 已知边界

- 同步任务的探测与业务探测共用渠道探测基建，单实例内存态；多实例部署下任务会重复执行（幂等保证安全，但有重复开销）。
