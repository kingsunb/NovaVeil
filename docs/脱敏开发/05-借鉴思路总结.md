## 一、占位符设计

### 1.1 格式：`{{LABEL_6位辅音}}`
**源码**：`transparent.py:636-681`（`_placeholder` / `_safe_label` / `_rand_suffix` / `_new_token`）

| 设计决策 | 理由 |
|---|---|
| 保留业务标签（PHONE/EMAIL/TERM） | 模型能理解"这里原本是个电话号"，回答质量不下降；旧格式用生僻 Unicode 不带语义，tokenizer 切成多个罕见 token，模型复述时变形 |
| 6 位**纯辅音**随机串 | 彻底消除大模型对十六进制数做变异算术的诱因（曾用 hex，模型把 `83fc6a` 当 IP 子网前缀做算术） |
| `secrets.choice` 而非 `random` | 后缀是会话内实体唯一标识，可预测会让上游能枚举/关联同一实体 |
| 生成时查重 20 次 | 避免与近期占位符冲突；实际不可达（20^6≈4700万，表里至多 2000 条） |

**踩坑**：兜底分支曾返回 `secrets.token_hex(6)`（12 字符），而还原正则只认 6 字符 → 该 token 永远匹配不到、还原永久失败且毫无声响。

## 二、多轮会话占位符复用

### 2.1 滑动窗口双向映射表
**源码**：`transparent.py:684-838`（`_RECENT_FWD` / `_RECENT_REV` / `_recall_token` / `_prune_recent`）

| 设计决策 | 理由 |
|---|---|
| 双向表：`FWD(原文→占位符)` + `REV(占位符→原文)` | 脱敏查 FWD，还原查 REV，O(1) |
| TTL 24h（独立于会话 TTL） | agent 任务动辄跑几十分钟，会话 TTL 600s 一到映射就清，模型回复里的占位符查不到原文 → 裸露给客户端 |
| 条数上限 2000 | 防无界增长；超出按时间戳淘汰最旧 |
| **滑动过期**：命中即续期 | 只在脱敏侧刷时间戳会导致"只出现一次后就再没脱敏但每轮被还原"的映射过期；还原侧也要刷（`_touch_recent`） |
| **不落盘** | 表里是原文明文，写盘等于把凭据写进磁盘，违反"凭据永不落库" |

### 2.2 防套娃
**源码**：`transparent.py:813-824`（`_recall_token` 开头）

如果原文自身就是占位符（多轮历史带入），**严禁为其分配新 token**，否则 A→B→C 无限套娃。先反查其真实明文，查不到就原样返回自身。

### 2.3 启动预热
**源码**：`transparent.py:742-810`（`_warmup_recent_from_db`）

引擎重启后客户端长对话里的历史占位符 100% 还原不了。从事件库只读预热 48h 内映射（凭据类只有 digest 没有原文，双重过滤不会被预热）。

**踩坑**：曾在该目录无库时静默回落 `%APPDATA%\Maskit`，导致隔离测试实例把生产库 420 条真实 PII 载入内存。

## 三、脱敏主流程

### 3.1 跳过已有占位符片段
**源码**：`transparent.py:1662-1691`（`_mask_excluding_placeholders`）

多轮对话历史里带旧占位符 `{{PHONE_bcdfgh}}`，自定义词里 2 字符的 hex 子串（如 `e3`）会把占位符劈开 → 畸形占位符 → 还原永久失败。

**解法**：用占位符正则把文本切成「占位符/非占位符」片段，只对非占位符片段做替换，占位符片段原样保留。

### 3.2 去重替换防 O(n²) 退化
**源码**：`transparent.py:1774-1796`

**踩坑**：同一个手机号在长上下文里出现上万次，逐次 `str.replace` → 整条管线退化成 O(命中次数 × 文本长度)。实测 256KB 请求体命中 11037 次、唯一原文仅 4 个，替换环节 930ms；512KB 达 3696ms，冻结全部 SSE 流。

**解法**：`dict.fromkeys` 去重保序后只对唯一原文替换一次。

### 3.3 特征预检
**源码**：`transparent.py:233`（`_rule_may_hit`）

每条规则先检查文本是否含必含特征（如身份证规则先查是否含连续数字），不含则跳过整条正则扫描，避免对每个请求跑全部 19 条正则。

### 3.4 递归脱敏 JSON 树
**源码**：`transparent.py:2028-2083`（`_mask_tree`）

响应结构五花八门，逐个格式硬编码必然漏。占位符只可能出现在脱敏过的位置，整树扫一遍是安全的。

**跳过策略**（踩坑提炼）：
- 按字段名整体跳过 name/url/id 会让 tool 参数里的业务字段（`input_name` 的姓名）原文直出
- **业务区**（`tool_use.input` / `function.arguments`）内一律照常扫描，不应用任何字段名豁免
- 业务区外按「完整路径 + 协议位置」判定，禁止裸字段名豁免
- JSON 深度超限不再静默放行：抛异常走 fail-closed 阻断

## 四、还原主流程

### 4.1 绝不做模糊匹配
**源码**：`transparent.py:1830-1886`（`_lookup`）

**踩坑**：曾加过"幻觉 IP 智能自愈"——模型把 `{{IPPRIVATE_83fc6a}}` 改写成 `{{IPPRIVATE_83fc00}}` 时，拿前 3-4 位 hex 匹配已知 IP，末两位当十进制主机位算出地址。结果 6 个从未登记的幻觉占位符里 5 个被编出地址，且编造的数据**是用户从未输入过的**。

**结论**：模型自造的占位符从来没被登记过，还原它在信息论上就不可能。正确行为是**原样保留 + 计入 unresolved**，让用户看得见"模型这里编了个东西"。

### 4.2 宽松第二遍兜底
**源码**：`transparent.py:1933-1951`

模型有时会剥掉占位符的花括号或只剩一半。严格第一遍后跑宽松第二遍，只认「查得到原文」的 token——查不到就原样放回，绝不猜。degraded 计数进事件让用户看得见"靠兜底修回来的"。

### 4.3 递归还原 JSON 树
**源码**：`transparent.py:1962-1977`（`_restore_tree`）

与非流式脱敏同理：整树扫一遍还原所有字符串叶子，天然覆盖 tool 调用参数。`arguments` / `partial_json` 字段是 JSON 文本，还原时原文需 JSON 转义，否则客户端解析工具参数报错。

## 五、流式 SSE 还原（最难，最值得借鉴）

### 5.1 按事件粒度处理
**源码**：`transparent.py:3191-3228`（`_restore_sse_event`）

一个 SSE 事件到手立刻还原、立刻下发，首字延迟才不会等于整段生成时长。

### 5.2 每个增量字段独立通道缓冲
**源码**：`transparent.py:3030-3096`（`_sse_text_slots`）

**踩坑**：正文 delta 与 tool 参数 delta 共用一个缓冲，会把上一个字段的尾巴吐进下一个字段，表现为字段被清空、内容错位。

**解法**：每个增量文本槽位用独立通道键（如 `c0.content` / `c0.tool0` / `a0.text`），半截占位符只在本通道缓冲。

**并行工具调用踩坑**：槽位键必须用 `tool_calls[].index`（协议标明这段增量属于第几个工具），不能用数组下标——并行工具调用时每个 chunk 通常只带一个元素，index=0 和 index=1 的增量都会拿到下标 0，两个工具的跨包缓冲直接串在一起。

### 5.3 中途块绝不能返回空字节
**源码**：`transparent.py:3334-3338`

**踩坑**：mitmproxy 的 ResponseData 分支不过滤空块，返回 `b""` 会按 chunked 语法写出 `0\r\n\r\n`——那正是**终止块**，客户端据此判定响应结束、停止读取并关连接。

**NovaVeil 对应**：handler 流式分支中途无事件返回空列表，不写出、不 Flush。

### 5.4 终止事件前必须吐净缓冲
**源码**：`transparent.py:3099-3110`（`_sse_is_terminal`）+ `3159-3188`（`_flush_pending`）

`[DONE]` / `finish_reason` / `message_stop` 等终止事件前，必须把各通道滞留的半截占位符补发出去，否则吞掉最后几个字。补发用最后一个同通道事件做模板（克隆真实事件保证客户端 SDK 字段校验通过），补发事件不能带 `finish_reason`。

### 5.5 CRLF 兼容
**源码**：`transparent.py:3304`

SSE 允许 CRLF；统一成 LF 后按空行切事件。此前只找 `\n\n`，CRLF 上游会把整段响应攒到流结束，客户端可能 chunk timeout 并截断。

### 5.6 usage 与文本留存解耦
**源码**：`transparent.py:3251-3265`（`_keep`）

usage 在流末最后几个 chunk 才出现，但文本留存有 256KB 上限：长回答会把带 usage 的尾部整个丢掉，"今日 Token 用量"永久少计。因此 usage 每块单独扫，不受留存上限影响。

## 六、校验函数（防误报）

**源码**：`transparent.py:410-612`

正则只能锁形状，校验函数锁真实性。每条都对应一个踩坑：

| 函数 | 校验内容 | 防的误报 |
|---|---|---|
| `_luhn_ok` / `_card_ok` | 银行卡 Luhn + 13-19 位 | 10 位串当卡号 |
| `_idcard18_ok` | 省份 + 真实日期 + ISO 7064 校验位 | 时间戳/雪花 ID 当身份证 |
| `_idcard15_ok` | 省份 + 19YY 真实日期 | 任意 15 位数字串 |
| `_phone_ok` | 1[3-9] 开头 + 排除全同号 | 11111111111 |
| `_landline_ok` | 0 开头 + 本地号首位 2-9 | 非法号段 |
| `_email_ok` | 合法用户名/域名 + TLD≥2 + 无连续双点 | 连接串误当邮箱 |
| `_iban_ok` | mod-97 余 1 | 任意字母数字串 |
| `_jwt_ok` | header base64 解码含 `alg` | 长 base64 串误判 JWT |

## 七、凭据安全

### 7.1 凭据只存 preview + digest
**源码**：`transparent.py:875-927`（`_cred_preview` / `_cred_digest` / `_redact_credentials`）

- 结构前缀（`sk-proj-`/`ghp_` 等）原样显示——不是秘密，是排查时最有用的信息
- 高熵凭据（API_KEY/ACCESS_KEY/TOKEN/JWT）显示「前缀 + 末 4 位」
- 低熵口令（SECRET/CONNSTR）不露首尾——10 位口令露首尾等于露了大半
- 事件库中凭据类恒只存 preview + sha256 摘要，导出剔除原文

### 7.2 NovaVeil 对应
NovaVeil 已有 `op/error_log.go:350` 的 `fieldSecretPattern`（日志字段 redact），可强化为同策略。

## 八、Fail-Closed 熔断

**源码**：`transparent.py:2037-2038`（`_mask_tree` 深度超限）

```python
if depth > _MASK_MAX_DEPTH:
    raise ValueError("json_depth_exceeded: 请求嵌套超过脱敏递归上限，拒绝透传")
```

JSON 深度超过上限不再静默原文放行：抛异常走 fail-closed 阻断，杜绝"深到扫不到就直出"的泄漏路径。

**NovaVeil 对应**：脱敏异常时调 `rejectRequest` 返回错误，绝不放行明文，契合 NovaVeil 现有错误处理风格。
