# 01 - 架构分析与精确插入点

> 本文档分析 NovaVeil 现有请求/响应链路，给出脱敏与还原的精确代码插入点。
> **本功能已实现**（2026-09-10，REQ-015），脱敏/还原已接入 `internal/relay/handler.go` 与 `internal/relay/mask_integration.go`。以下行号为设计时参考，以实际代码为准。

---

## 一、请求/响应完整链路

```text
客户端请求
  ↓
handler.go:Forward(format)                        # 转发入口（relay/handler.go:34）
  ↓
readLimitedHTTPRequest(c.Request)                 # 读取请求体（handler.go:53）
  ↓
requestBodyString := string(raw.Body)              # 请求体安全拷贝（handler.go:88）
  ↓
op.GroupGetByName(metadataModel)                  # 按模型名找分组（handler.go:75）
  ↓
for {                                             # 转发循环（handler.go:122）
  pickGroupItem(group, exclude, format)           #   选成员（handler.go:173）
  resolveGroupRefChain(...)                       #   解析引用链到叶子成员（handler.go:190）
  op.ChannelGetCore(channelModel.ChannelID)       #   取渠道（handler.go:245）
  ↓
  sendPassthrough / sendConverted                 #   发往上游（upstream.go:66）
    buildPassthroughRequest(format, raw, ...)     #     构建上游请求
    helper.ChannelHttpClient(&channel)            #     取 HTTP 客户端（含代理）
    client.Do(request)                            #     发起上游请求
  ↓
  upstreamResponse{body / events}                 #   上游响应（upstream.go:33）
}
  ↓
响应回写客户端：
  非流式: c.Writer.Write(result.body)             # handler.go:552
  流式:   c.Writer.Write(encoded.Bytes())         # handler.go:713 / 792
          c.Writer.Flush()                        # handler.go:725 / 795
```

### 关键特征
- **单进单出**：同一时刻只走一个上游，故障转移是串行轮试。
- **安全拷贝**：`handler.go:88` 以 `string(raw.Body)` 复制请求体独立副本，每轮改写由 sjson 生成新切片，不原地改写 `raw.Body`（原 `unsafe.String` 零拷贝已在安全审计 C-1 中改为安全拷贝）。
- **协议感知**：`Forward(format)` 已按 `OpenAI / OpenAIResponses / Anthropic` 分流，脱敏可复用此判断。

## 二、脱敏插入点（请求方向）

### 位置：`internal/relay/handler.go` 约第 88 行之后

```go
// 现有代码（handler.go:88）
requestBodyString := string(raw.Body)

// 【脱敏插入点】在此处对 requestBodyString 扫描替换为占位符
// 生成新切片，不原地改写 raw.Body，契合现有安全拷贝模式
if maskEnabled(group) {
    maskedBody, mapping := mask.Engine.Apply(requestBodyString, sessionKey)
    requestBodyString = maskedBody
    // mapping 保存到请求状态，供响应还原使用
    request.maskMapping = mapping
}
```

### 为什么在这里

（因果背景，见 agent note；）

1. **请求体已完整读入**（`readLimitedHTTPRequest` 在前）。
2. **分组已确定**（`op.GroupGetByName` 在前），可按分组判断是否启用脱敏。
3. **尚未发往上游**（`sendPassthrough` 在后），脱敏后上游收到的是占位符。
4. **每轮重试复用**：循环内每轮用同一脱敏结果，不重复扫描。

### 注意事项
- `raw.Body` 是 `[]byte`，脱敏后需同步更新用于后续 `gjson.GetBytes` 等读取的字段。
- 脱敏异常时走 **Fail-Closed**：调 `rejectRequest` 返回错误，绝不放行明文。
- **开关关闭时开销**：`maskEnabled(group)` 为 `false` 时跳过正则扫描与缓冲分配，但关闭路径仍会读取/解析配置（`MaskConfigGet` 走 `settingCache`），不能宣称仅一次 bool 判断或零开销（对齐 `README.md` 第八节第 4 条）。响应侧 `request.maskMapping == nil` 时还原为 no-op。

## 三、还原插入点（响应方向）

### 3.1 非流式响应

**位置：`internal/relay/handler.go` 约第 552 行之前**

```go
// 脱敏还原: 非流式响应占位符→原文(文档 01 §3.1)。
result.body = restoreNonStream(result.body, maskMapping)
n, err := c.Writer.Write(result.body)
```

### 3.2 流式 SSE 响应

**位置：`internal/relay/handler.go` 第 771 行（`sse.Encode` / `c.Writer.Write` 之前）**

```go
// 脱敏还原: SSE 事件增量文本占位符→原文, StreamRestorer 跨 chunk 缓冲拼接(文档 01 §3.2、03)。
if streamRestorer != nil {
    event.Data = restoreStreamEvent(event.Data, format, streamRestorer)
}
chunks = append(chunks, event)
encoded.Reset()
if encErr := sse.Encode(&encoded, sse.Event{Id: event.LastEventID, Event: event.Type, Data: event.Data}); encErr != nil {
    ...
}
n, writeErr := c.Writer.Write(encoded.Bytes())
```

流结束若 `StreamRestorer` 仍缓存未闭合占位符，`flushStreamRestorer` 会在尾帧补一次冲刷。

### 为什么在这里

（因果背景，见 agent note；）

1. **上游响应已取得**，即将写给客户端。
2. **流式逐 event 写出**，还原须在 `Write` + `Flush` 前。
3. **还原发生在 `event.Data` 层（未编码文本）而非 `encoded` 字节缓冲**，`sse.Encode` 之后原样写出；流结束若还有未闭合占位符，`flushStreamRestorer` 再补一次冲刷（见 03）。

sessionKey := c.GetHeader("X-Session-Id")

## 六、与现有日志 redact 的关系

`internal/op/error_log.go:350` 已有 `fieldSecretPattern`，用于**记录错误日志时**把 authorization/password 等字段值打码。

| | 现有日志 redact | 新增请求脱敏 |
|---|---|---|
| 作用环节 | 日志记录 | 请求出网 + 响应回写 |
| 作用对象 | HTTP 头字段值 | 请求/响应正文内容 |
| 目的 | 防日志泄密 | 防上游模型看到真实数据 |

两者互补，不冲突。
