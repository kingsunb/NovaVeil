## 一、配置模型

### 1.1 全局配置（系统设置）

复用 NovaVeil 现有 `internal/model/setting.go` 系统设置机制。

```go
// internal/model/mask_setting.go
type MaskConfig struct {
    Enabled            bool            `json:"enabled"`              // 全局总开关，默认 false
    BuiltinRuleSwitch  map[string]bool `json:"builtin_rule_switch"`  // 12 类规则开关，默认全 false
    CustomTerms        []CustomTerm    `json:"custom_terms"`         // 自定义敏感词
    SessionMappingTTL  int             `json:"session_mapping_ttl"`  // 会话映射表存活秒数，默认跟随会话粘合
}

type CustomTerm struct {
    Value    string `json:"value"`     // 敏感词原文
    Category string `json:"category"`  // 分类，如 "人名"/"项目代号"
}
```

### 1.2 分组级开关

在 `internal/model/group.go` 的 `GroupRelayConfig` 加字段：

```go
type GroupRelayConfig struct {
    // ... 现有字段 ...
    MaskEnabled bool `json:"mask_enabled"` // 是否对本分组启用请求脱敏，默认 false
}
```

### 1.3 作用优先级
```
分组 MaskEnabled=false → 不脱敏（即使全局开）
分组 MaskEnabled=true  + 全局 Enabled=true → 按全局规则脱敏
全局 Enabled=false     → 全局不脱敏（无论分组设置）
```

### 1.4 默认关闭语义（硬约束）

出厂状态恒为全关，且为不可退化的硬约束（非可配置倾向）：

1. **全局开关**：`Enabled` 默认 `false`。复用 `SettingGetBool`，**setting 行不存在即视为关，无需初始化写入默认行**（与 `SettingKeyConversationLog` 完全一致）。
2. **分组开关**：`MaskEnabled` 为 `bool` 零值 `false`，旧分组 JSON 反序列化自动得关，**无需数据迁移**。
3. **单规则开关**：`BuiltinRuleSwitch` 出厂恒为全 `false`，不提供任何默认开启项。
4. **热生效**：开关走 `settingCache`，管理台改写即刷新，**无需重启**。

## 二、管理 API

### 2.1 配置读写

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mask/config` | 读取脱敏配置 |
| PUT | `/api/mask/config` | 更新脱敏配置（全局开关、规则开关、自定义词） |

### 2.2 规则元信息

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mask/rules` | 12 类内置规则元信息（标签、说明、默认开关） |

### 2.3 脱敏测试

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/mask/test` | 输入文本 → 返回脱敏结果 + 映射表（不入库、不转发，供管理员预览规则效果） |

请求示例：
```json
{ "text": "排查 mysql://root:Pass123@192.168.1.50:3306 联系李四 13800138000" }
```
响应示例：
```json
{
  "masked": "排查 {{CONNSTR_zkpmqx}} 联系{{TERM_fnqtsw}} {{PHONE_bcdfgh}}",
  "matches": [
    {"label": "CONNSTR", "original": "mysql://root:Pass123@192.168.1.50:3306", "placeholder": "{{CONNSTR_zkpmqx}}"},
    {"label": "TERM", "original": "李四", "placeholder": "{{TERM_fnqtsw}}"},
    {"label": "PHONE", "original": "13800138000", "placeholder": "{{PHONE_bcdfgh}}"}
  ]
}
```

> 注意：`/api/mask/test` 返回原文映射仅供管理员预览，**绝不写日志**，响应后即丢弃。

### 2.4 handler 位置
`internal/server/handlers/mask.go`，路由注册在 `internal/server/router/`。

## 三、前端管理页

### 3.1 页面结构

```
web-next/src/pages/mask/
  ├── MaskPage.tsx          # 脱敏管理主页
  ├── RuleList.tsx          # 12 类规则开关列表
  ├── CustomTerms.tsx       # 自定义敏感词管理
  ├── MaskTester.tsx        # 脱敏效果测试器（实时预览）
  └── GroupMaskToggle.tsx   # 分组级开关（嵌入现有分组编辑页）
```

### 3.2 功能
1. **全局开关**：一键启停。
2. **规则开关列表**：12 类规则，每条显示标签 + 说明 + 开关，参考 maskit `BUILTIN_RULE_META`。
3. **自定义敏感词**：按分类增删改，整词匹配。
4. **脱敏测试器**：左输入框输入文本，右实时显示脱敏结果 + 命中明细，供管理员调规则。
5. **分组开关**：在现有分组（Group）编辑页加一个「启用脱敏」开关。

### 3.3 样式规范
遵循 NovaVeil 现有前端规范：Tailwind + 现有 UI 组件（`web-next/src/components/ui/`），中英双语（参考 `web-next/src/lib/` i18n）。

## 四、审计可视化（可选增强）

## 五、凭据安全强化

NovaVeil 已有 `op/error_log.go:350` 的 `fieldSecretPattern`（日志字段 redact）。
引入脱敏后须强化：

1. **脱敏映射表不落库**：`Mapping`（占位符↔原文）仅在内存，请求结束即回收，绝不持久化。
2. **日志中的占位符**：日志记录请求体时记录**脱敏后**的占位符版本，不记录原文。
3. **`/api/mask/test` 响应**：仅管理员可调用，响应不写日志。
4. **凭据类规则命中**：API_KEY/TOKEN/SECRET 等命中时，日志只存 preview + sha256 摘要（对齐 maskit 凭据安全红线）。

## 六、与 NovaVeil 现有功能的关系

| 现有功能 | 关系 |
|---|---|
| 日志 redact（`error_log.go`） | 互补：redact 管日志记录，脱敏管出网 |
| 会话粘合（`X-Session-Id`） | 复用：映射表挂到会话 |
| 故障转移（`route.go`） | 兼容：脱敏在转发前，故障转移重试复用同一脱敏结果 |
| 协议转换（transformer） | 复用：按协议判断 SSE 文本字段 |
| 分组配置（`GroupRelayConfig`） | 扩展：加 `MaskEnabled` 字段 |
| 系统设置（`setting.go`） | 复用：全局脱敏配置 |
