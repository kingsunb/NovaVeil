> **状态：已实现**（2026-09-10，REQ-015；2026-09 扩展 MAC/USCC 两规则）。规则引擎代码见 `internal/relay/mask/rules.go`、`placeholder.go`、`engine.go`。本文档为设计参考。

## 一、占位符规范

### 1.1 格式
```
{{LABEL_后缀}}
```
- `LABEL`：规则类型标签，如 `PHONE`、`CONNSTR`、`API_KEY`、`TERM`（自定义敏感词）。
- `后缀`：**6 位纯辅音随机串**，如 `zkpmqx`、`bcdfgh`。

### 1.2 为什么用 6 位辅音串

（因果背景，见 agent note；）maskit 的设计理由：彻底消除大模型对十六进制数做变异算术的诱因。纯辅音串不含元音与数字，不像是任何编码/哈希，模型不会尝试对它做运算。

### 1.3 Go 实现
```go
// internal/relay/mask/placeholder.go
var consonants = []byte("bcdfghjklmnpqrstvwxz") // 20 个辅音

func genSuffix() string {
    b := make([]byte, 6)
    for i := range b {
        b[i] = consonants[secureRand.Intn(len(consonants))]
    }
    return string(b)
}
```
使用 `crypto/rand` 保证随机性，避免可预测。

## 二、12 类内置规则

译自 maskit `shield_defaults.py:102`（`DEFAULT_BUILTIN_RULES`）与 `transparent.py:52`（`RULES`），并按 NovaVeil 实际实现收敛为 12 类。

### 2.1 规则清单

| 标签 | 说明 | 默认开关 | 正则特征 |
|---|---|---|---|
| `PRIVATE_KEY` | PEM 私钥整块替换 | 关 | `-----BEGIN ... PRIVATE KEY-----` 到 `-----END...` |
| `API_KEY` | GitHub PAT / Google / Slack / Stripe / OpenAI / 钉钉 | 关 | `gh[pousr]_`/`github_pat_`/`AIza`/`xox`/`sk-`/`[sr]k_(live\|test)_`/`cli-`/`ding-`；预检前缀表须与正则同步，否则纯前缀文本被整条跳过 |
| `CONNSTR` | 数据库连接串密码（只脱密码组） | 关 | `scheme://user:pass@host`，保留 scheme/user/host |
| `PHONE` | 手机号（含 +86、分隔符） | 关 | 11 位连续 / `138-1234-5678` / `86138...` |
| `EMAIL` | 邮箱 | 关 | 标准邮箱正则 |
| `IDCARD` | 身份证（18 位二代） | 关 | 省份+日期+校验位校验 |
| `CARD` | 银行卡（Luhn 校验） | 关 | 13-19 位 + Luhn 算法校验 |
| `SECRET` | password=/token=/api_key= 赋值凭据 | 关 | 中英文关键词 + 赋值符，值须含数字/符号 |
| `JWT` | JWT | 关 | `eyJ...` 三段式 |
| `TOKEN` | Bearer Token | 关 | `Bearer xxx` |
| `MAC` | MAC 地址 | 关 | 6 组十六进制（冒号链须恰 6 组/连字符/点）+ 词边界，校验冒号链组数（防截断 IPv6） |
| `USCC` | 统一社会信用代码 | 关 | 18 位 31 进制限字符集（禁 I/O/S/V/Z）+ MOD 31 校验位 |

### 2.2 默认开关策略

（因果背景，见 agent note；）以下为默认全关的取舍：

- maskit：默认开 7 类核心（API_KEY、CARD、CONNSTR、EMAIL、IDCARD、LANDLINE、PHONE）。
- **NovaVeil 硬约束：默认全关，管理员按需开启**。原因：NovaVeil 面向网关多用户，误报影响面更大；首次引入应保守。此为不可退化的出厂保证（详见 `README.md` 第八节），`BuiltinRuleSwitch` 不提供任何默认开启项。

### 2.3 Go 规则结构
```go
// internal/relay/mask/rules.go
type Rule struct {
    Label       string         // 规则类型标签，如 "PHONE"
    Pattern     *regexp.Regexp // 编译后的正则
    Group       int            // 捕获组号，0 表示整匹配替换；CONNSTR=1 只脱密码组
    Description string         // 规则说明
}

// RuleMeta 规则的对外元信息，供配置层展示与默认开关判定。
type RuleMeta struct {
    Label          string `json:"label"`
    Description    string `json:"description"`
    DefaultEnabled bool   `json:"default_enabled"`
}

var BuiltinRules = []Rule{
    {Label: "PRIVATE_KEY", Pattern: regexp.MustCompile(`-----BEGIN ... PRIVATE KEY-----...`), Group: 0},
    {Label: "API_KEY", Pattern: regexp.MustCompile(`gh[pousr]_[A-Za-z0-9_]{20,}`), Group: 0},
    // ... 其余 10 类
}

// 默认开关由 BuiltinRuleMeta 统一声明（硬约束：全部 false）。
var BuiltinRuleMeta = []RuleMeta{
    {"PRIVATE_KEY", "PEM 私钥整块替换", false},
    {"API_KEY", "GitHub PAT / Google / Slack / Stripe / OpenAI / 钉钉 凭据", false},
    // ... 其余 10 类
}
```

### 2.4 边界处理（译自 maskit 踩坑记录）

（因果背景，见 agent note；）maskit 每条规则的注释记录了踩过的坑，移植时须保留：
- **IP 右边界**：额外挡掉 `.\d`，避免 `编号 192.168.1.1.1` 截半。
- **SECRET 值排除 `{}`**：避免占位符被二次替换（`api_key=sk-xxx` → 占位符 → SECRET 再包一层）。
- **SECRET 值须含数字/符号**：纯字母标识符（CamelCase 方法名）不误报。
- **SECRET 中英文关键词**：同时覆盖 `password`/`密码`/`口令`/`令牌`/`密钥` 等，分隔符同时覆盖半角 `:=` 与全角 `：＝`。
- **CONNSTR 只脱密码组**：保留 scheme/user/host，模型仍能理解这是连接串。
- **手机号 +86 整体脱敏**：避免国家码原文残留。

## 四、多轮会话一致性

### 4.1 问题
同一长对话中，「张三」在第 1 轮和第 10 轮必须映射为**同一个占位符**，否则大模型上下文逻辑混乱。

### 4.2 设计：滑动窗口映射表

```go
// internal/relay/mask/session.go
type Mapping struct {
    Forward map[string]string // 原文 → 占位符（脱敏用）
    Reverse map[string]string // 占位符 → 原文（还原用）
}

type SessionStore struct {
    mu       sync.RWMutex
    sessions map[string]*Mapping // sessionKey → Mapping
}
```

- **脱敏时**：命中敏感值 → 查 Forward 表；已有则复用占位符，没有则生成新占位符并双向登记。
- **还原时**：占位符 → 查 Reverse 表 → 替换原文。
- **会话回收**：随 NovaVeil 会话粘合过期（`SessionStickySeconds`）一并回收映射表，防内存泄漏。

### 4.3 无会话标识时
客户端未传 `X-Session-Id` 时，使用请求级临时映射表（仅本轮有效，不复用）。

## 五、脱敏引擎主流程

```go
// internal/relay/mask/engine.go
type MaskResult struct {
    Masked  string   // 脱敏后的文本
    Mapping *Mapping // 本轮会话映射表(供还原用)
    Matches []Match  // 命中明细
}

type Match struct {
    Label       string // 规则标签，如 PHONE / EMAIL / SECRET / TERM
    Original    string // 命中原文
    Placeholder string // 替换占位符，如 {{PHONE_bcdfgh}}
}

func (e *Engine) Apply(body string, sessionKey string, enabledRules map[string]bool, terms []CustomTerm) (MaskResult, error) {
    mapping := e.store.GetOrCreate(sessionKey)
    result.Mapping = mapping

    // 规则集: 自定义词(TERM)在前, 其后为开启的内置规则(按 BuiltinRules 顺序)。
    rules := termRules(terms)
    for _, rule := range e.rules {
        if enabledRules[rule.Label] {
            rules = append(rules, rule)
        }
    }

    maskText := func(text string) string {
        return maskCandidates(text, rules, mapping, &result.Matches, seen)
    }

    result.Masked = body
    if len(rules) != 0 {
        if 是合法 JSON 文本(首字符为 {/[ 且整体 json.Valid) {
            // 仅扫描解码后的字符串值, 键名与非文本字段原样。
            result.Masked = mapJSONStringValues(body, maskText)
        } else {
            result.Masked = maskText(body)
        }
    }
    return result, nil
}
```

### 候选收集与一次替换

引擎不在每条规则命中后立即替换——旧法会让先生成的占位符切碎后续规则的完整命中（如
`token=<SECRET>.<载荷>.<签名>` 让 JWT 规则看不到三段式整体）。现行 `maskCandidates`
对所有规则在原文上统一收集候选，排序后贪心选一组互不重叠的区间，一次替换完成：

1. 候选排序：`origStart` 升序 → 自定义词(TERM)优先 → `origEnd` 降序（同起点长匹配优先，
   如 CONNSTR 完整密码整体覆盖 API_KEY 前缀命中，不残留 `.tail` 尾巴）→ `ruleIdx` 升序；
2. 与已选区间重叠的候选丢弃，不产生嵌套占位符；
3. 已有占位符片段不参与收集与替换，多轮会话占位符稳定；
4. 每条规则先特征预检（`ruleMayHit`），命中候选再过校验函数（`builtinValidators`），不过则丢弃。

JSON 请求体仅对**解码后的字符串值**执行扫描与替换，键名、数字、布尔等非文本字段不参与匹配——
否则 `\"`、`\u0031` 等转义形态会绕过全部正则。已知限制：还原是纯文本替换、不按 JSON 重新转义，
原文含引号/换行等 JSON 特殊字符时回填会破坏响应体转义（机密内容本身仍完整还原）。

### 执行顺序
1. 自定义敏感词（整词，长词优先）
2. PEM 私钥（整块，最高危）
3. 其余正则规则：候选统一收集后一次替换（同起点长匹配优先，同长度按 `BuiltinRules` 顺序）

（因果背景，见 agent note；）顺序原因：先做整词再做正则，避免正则把敏感词拆碎后无法整词匹配。

> **命中明细（`Matches`）**：引擎每次 `Apply` 均产出 `[]Match`（按唯一原文去重保序）。`applyRequestMask` 现直调 `mask.Engine.Apply` 并返回 `res.Matches`，经 `truncateMaskMatches` 裁剪后透传进 `RequestState`，随日志详情下发命中原文片段。日志详情展示命中明细的设计见 [07-日志详情命中明细.md](07-日志详情命中明细.md)。
