# NovaVeil 稳定性与体验基线

> 目标：记录后续稳定性、性能和前端体验改造的共同验收口径。
> 当前仓库是整理与 CI 验收仓；正式发布仍归属 `kingsunb/NovaVeil`。

## 前端验收矩阵

每个面向用户的改动至少检查以下组合：

- 视口：1440px 桌面、768px 平板、390px 移动端
- 主题：浅色、深色
- 状态：加载中、成功、空数据、请求失败、重试成功
- 交互：键盘 Tab/Enter/Escape、焦点可见、弹窗焦点回收
- 可访问性：交互态 axe 检查、按钮和表单控件有可识别名称
- 性能：无意外横向滚动；大列表保持虚拟化；减少常驻 blur 和无意义重渲染
- 动效：`prefers-reduced-motion` 下不依赖动画传达信息

真实数据优先于装饰性占位。没有后端时间序列接口时，不展示看起来像真实趋势的静态图。

## 后端稳定性验收矩阵

重点覆盖以下边界：

- 静态资源高频访问不会持续泄漏文件句柄
- 上游 4xx/5xx 巨大响应只读取受限诊断片段
- 对话写盘失败不会清空未确认落盘的队列
- writer Flush 后不会继续接受进入无人消费队列的新记录
- 关闭流程等待或取消正在运行的 DB/IO 任务
- 渠道和分组缓存发布不会出现 Clear 与逐项 Set 之间的空快照
- 大压缩请求受解压后体积和并发内存预算约束
- 资源饱和与上游故障分开计数，不因正常排队触发熔断
- 并发登录限流具备原子语义

## 观测指标方向

后续统一补充可聚合指标，而不是只依赖日志：

- relay 请求总延迟、首字节延迟、尝试数、失败分类、重试和冷却
- 渠道并发/RPM 等待、资源饱和次数
- SSE watcher 数、断线重连和认证失败
- conversation 队列深度、写盘失败、丢弃数和 housekeeping 耗时
- 后台任务跳过/失败、shutdown 超时
- DB pool 使用情况和代理 Transport 缓存命中/淘汰

## CI 验收

CI 为验收门禁；本地构建/测试不被禁止（见 CONTRIBUTING、AGENTS.md 常用命令）；改动推送后由 GitHub Actions 执行 Go、Vitest、Playwright、a11y、镜像和安全扫描。每个主题拆成独立 PR，行为修复必须带针对性测试。
