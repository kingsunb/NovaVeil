## 1. 状态口径

- **代码已有**：可以定位实现，不代表测试通过、已部署或完整需求全部完成。
- **待实施**：本轮核对的路径中仍存在实现缺口。
- **待复核**：存在静态风险或文档与代码差异，需要进一步确认，不能直接写成线上故障。
- **待验收**：由远端环境、用户或 CI 提供当前版本的执行结果；测试源码存在不算验收证据。

历史审计按形成时的快照阅读。例如旧报告中的 `unsafe.String` 和 timer 未停止条目不能直接搬入当前缺陷清单：当前 relay 路径已使用字符串拷贝及显式停止 timer。功能记录的“已完成”也不替代逐项契约核对。

## 3. 第一批：部署与业务契约收口

优先级表示实施顺序，不是安全漏洞评级。此批先消除可能让部署失败或误解路由行为的问题，不新增产品范围。

### 3.1 部署说明与模板一致性（待复核 / 待修订）

当前依据：`internal/conf/config.go`、`docker-compose.yml`、`docker-compose.local.yml`、根双语 README 与 `docs/SECURE_DEPLOYMENT.md`。

- [ ] 将直接运行的默认监听地址 `127.0.0.1` 与容器显式配置的 `0.0.0.0` 分开说明；补齐 `server.trusted_proxies` 与 `security.cookie_secure` 的配置边界。可信代理已有配置入口，不应再引导用户修改应用代码。
- [ ] 在远端复核 Compose 插值：可选前端服务使用 `NOVAVEIL_WEB_NEXT_IMAGE` required 插值，可能在 profile 筛选前影响默认单容器路径。本轮未执行 Compose，不能断言已经复现。
- [ ] 校正本地容器示例的 `-f docker-compose.local.yml` 选择，并统一独立前端 Dockerfile 与正式 CI 的 pnpm 工具链要求；不以文档更新代替实际镜像验证。

**验收标准**：默认部署不要求未启用组件的变量；显式启用独立前端时才校验其必需参数；直跑与容器的监听、代理信任、Cookie 和健康检查行为均有对应配置及记录。

### 3.2 模型评估与分组契约（代码已有，文档待收口）

当前依据：`internal/server/handlers/model_eval_rank.go`、`internal/op/model_eval_rank.go`、`internal/op/group.go`、`internal/eval/scheduler.go`。

- 当前自动生成目标是 **`auto` 分组**，接口仍沿用 `/rank/apply-pro` 命名。成员写入 `priority = i + 1`，**数值越小越优先**，替换已有事务保护。不要再规划从零实现事务替换，也不要套用渠道列表“数值越大越靠前”的 sort 语义。
- 排序接受 `ok` 与 `violation`，按 position 排列；`error` 不更新排序，已有成功快照可能保留，更新已有条目也保留位置。并非“ok 自动分区在前、error 留在底部、无条件只保留最新一次评估”。
- 调度器已有最多 4 个并发 worker；10 分钟限制是**任务开始执行后的超时**，不是排队等待上限。

- [ ] 将 REQ-024 的 `pro`、priority 方向、结果分类和超时描述与上述实现逐项对齐，保留历史设计意图与现行契约的区别。
- [ ] 统一前端排序、历史复用与提示对 `violation` 的资格描述。推荐以现有“最近成功快照 + 人工排序”作为本轮维护基线；若需改成失败覆盖、自动分区或改变历史复用资格，应单独明确产品行为后实施。
- [ ] 验证替换事务失败回滚、排序后真实路由顺序、失败评估不覆盖成功快照、队列重启恢复、关闭期间落盘以及 SSE 重连。

### 3.3 路由与渠道历史任务（文档待校正，代码待回归）

当前依据：`internal/relay/handler.go`、`internal/op/channel.go`、`internal/op/channel_sort_test.go`。

- [ ] 校正路由文档“失效引用在本请求永久排除且不等待”的绝对表述。当前实现是单次解析失败不记失败、不进冷却；无候选或结构性跳过过多时允许退避并重新评估，不是永久排除集合。
- [ ] 将渠道优先级零值写入的旧排查建议视为历史记录。已有显式 sort 写入和用例，剩余是“非零改为 0 后刷新”“负数与同值”“连续编辑失败恢复”的真实接口与界面回归。

**验收标准**：多个坏引用与可用叶子混合时仍可完成请求；全组不可用不热旋，恢复与取消可正确结束等待；渠道优先级保存及重载一致。

## 4. 第二批：安全可观测性与资源约束

### 4.1 脱敏日志命中摘要（待实施）

以 [07-日志详情命中明细](脱敏开发/07-日志详情命中明细.md) 为唯一详细方案入口。

- [ ] 先确定安全摘要结构、字段上限和截断行为，再打通请求状态、SSE、前端详情；错误日志持久化作为后续独立步骤。
- [ ] 不直接将测试预览中的 `{label, original, placeholder}` 明文映射复制到请求日志。尤其凭据、令牌、私钥不可因“便于排查”进入 SSE、数据库或浏览器存储。
- [ ] 对 MAC/USCC 工作区扩展安排规则边界、校验、默认关闭和规则顺序回归；不将未提交实现写成已发布功能。

**验收标准**：有命中时可解释规则与去重后的明细数量，不冒充原文出现次数；无命中和功能关闭时无额外明文字段；命中摘要有容量上限；日志各出口及流式恢复没有新增敏感值泄漏。另需复核脱敏前请求状态已创建并发布的暂存时序，本次摘要方案不等于请求体接口在所有时刻都已受保护。

### 4.2 请求体并发内存预算（待实施）

`internal/relay/bodylimit.go` 已限制压缩请求体 16 MiB、解压体 64 MiB，但路径仍按请求完整读入内存。本轮在请求体读取/解压阶段未见全局加权预算，单请求上限不能证明并发峰值受控。

- [ ] 在读取和解压阶段引入可取消、可回收的总预算；明确超限拒绝/等待策略、配置默认值及观测字段。
- [ ] 在远端验证并发大请求、压缩体扩张、客户端取消及错误路径，检查额度释放与峰值内存；不在本机进行负载测试。

**验收标准**：峰值有明确预算约束，所有结束路径释放额度，拒绝行为可解释且不影响正常小请求。指标与关闭流程复用 [稳定性基线](STABILITY_UX_BASELINE.md)，不另建互相冲突的标准。

## 5. 第三批：前端体验与性能

详细任务与局部优先级见 [路由性能规划](frontend-redesign/ROUTE_TRANSITION_PERFORMANCE_PLAN.md) 和 [生产前端后续计划](frontend-redesign/FOLLOW_UP.md)。局部 P0/P1 编号只在各专项内排序。

1. 先补路由分类骨架、主内容滚动复位和导航 chunk 预加载，保留已有 lazy chunk 结构。
2. 同步收口移动抽屉焦点、命令面板可发现入口、窄屏工具栏及错误/空态区分。
3. 对 Logs 高频 SSE、Groups 卡片与 Dashboard 派生计算先采样再优化，不重复包装已有 `useMemo`。
4. 保留取消在途查询、保存响应直接回填缓存的交互；后台失效刷新不能重新变成保存反馈的前置条件。

**验收标准**：实际生产构建覆盖深浅主题、桌面及窄屏、键盘操作、慢请求与失败恢复；性能改动有前后测量，不能以原型截图或源码结构替代浏览器验收。
