# Agent Note: 会话与代理账号粘合（出站身份按出口隔离）

Status: implemented

## 问题

免费档的出口身份策略此前是「**会话扇出**」：出站会话标识按请求内容派生后，选号时**排除**本会话已用过的代理账号（`sessionUsed` 去重）——同一会话的多轮请求会**扇出**到多个 resin 出口/WARP 槽位。上游免费层按「会话标识 + 出口」做关联记账：**同一个 `ses_` 从多个出口 IP 出现是典型的关联标记信号**，恰是身份惩罚的诱因之一。此外账号池的 429 两会话计票所用的会话标识也是跨出口漂移的，计票语义被稀释。

## 决定

**会话与代理账号粘合**，两个改动点：

1. **账号池粘合**（`internal/relay/opencode_proxy_pool.go`）：`sessionUsed`（去重表）改为 `sessionBound`（粘合表）——同一会话粘合键恒定绑定同一账号，绑定账号可用即复用；绑定账号冷却/淘汰/失败降级不可用时才换号改绑（换号排除旧绑定，改绑后不回跳），换号即清该会话的 429 计票痕迹（改绑后出站标识已更新）。粘合记录带 TTL（`ocProxySessionTTL`）与淘汰联动（账号被清理时删除其粘合）。
2. **出站会话按账号派生**（`internal/utils/opencodeid/identity.go` 新增 `DeriveSessionIDForAccount` + `internal/relay/handler.go` 接线）：出站 `ses_` = 派生（客户端信号 + 账号）——同一（信号, 账号）**恒定**同一出站会话（prompt cache/亲和不受损），**账号变更必然换号**（信号混入账号后官方形态校验必然失效，强制派生新号）。粘合键（不含账号的派生值）与出站值分离：跨 failover 轮次粘合键稳定，出站值随账号走。

WARP 槽位渠道不走账号池，行为不变（按会话去重槽位）；探针路径自铸会话，不受影响。

## 备选方案

- **维持会话扇出**：设计初衷是分散单账号额度，但把关联标记的指纹亲手交给上游——429 惩罚实测按身份记账，扇出得不偿失。
- **仅换号不改出站会话**：同一 `ses_` 立刻从新出口出现，关联信号更强，等于没修。
- **粘合放在响应侧还原**：身份已经泄给上游才还原，晚了。

## 后果

- **收益**：同一会话在同一个出口上呈现连续身份（与真实客户端单机行为一致）；429 两会话计票的「会话」语义恢复真实（计票会话 = 出口隔离的独立身份）；客户端不做任何改动。
- **代价**：单会话的额度集中在单一账号上（不再扇出摊薄），账号额度耗尽靠换号改绑承接，换号即换身份（该会话在上游的记账/prompt cache 从零开始——这正是隔离的目的）；`sessionBound` 常驻内存（TTL 与淘汰联动清理）。
- **兼容**：面板手动体检显式模型不受影响；WARP 槽位路径不变；探针自铸会话不变。

## 验证

```sh
go test ./internal/relay/ -run 'TestOcProxyPool' -v
go test ./internal/utils/opencodeid/ -v
```

- `TestOcProxyPoolPickSessionSticky`：粘合命中复用、失效换号改绑、改绑不回跳、独立会话互不影响。
- `TestDeriveSessionIDForAccount`：同（信号, 账号）恒定、换账号必换、空账号等价原派生、形态合法。
- 线上验证：同一会话连续多轮请求，抓包确认出站 `ses_` 恒定且 `x-opencode-request` 逐轮递进；触发账号冷却后确认会话换绑至新账号且出站 `ses_` 随之更新。
