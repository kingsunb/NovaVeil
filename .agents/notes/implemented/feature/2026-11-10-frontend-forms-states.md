# Agent Note: 管理页表单校验、列表三态与开关可访问性

Status: implemented

## 问题

管理页存在三类会误导操作者的问题。第一，打开新建弹窗即显示必填错误，用户尚未输入就先看到红字；保存按钮又被禁用，无法通过提交触发表单级校验。第二，代理体检页把渠道或台账请求失败渲染成「没有可体检的渠道」「台账为空」，让网络故障看起来像真实空数据。第三，多处开关只有视觉上的相邻文案，没有可访问名称，屏幕阅读器只能读「开关」；修改密码输入框也只有 placeholder。

## 决定

- 开关补齐可访问名称：脱敏全局总开关、内置规则、代理自动体检、自定义模型启停、对话留存、转换追踪、分组自动匹配均使用 `aria-label`。修改密码的当前密码与新密码使用 `aria-label`，确认密码原有名称保留。
- 代理体检页的渠道列表与台账都区分三种状态：请求中显示 `TableSkeleton`，失败显示 `QueryErrorBanner` 并提供重试，成功且为空才显示 `EmptyState`。台账空态按筛选条件区分「台账为空」与「当前筛选下没有账号」。
- 脱敏新增词弹窗与自定义模型编辑器采用 touched/submitted：字段失焦或点击保存后才显示校验错误；自定义模型保存按钮不再因本地校验未通过而禁用，点击后展示全部错误并阻止请求。错误直接由当前输入实时计算，输入变化后立即消失。多行固定回复用 `aria-invalid` 表达无效态。
- 删除、批量删除继续使用现有确认弹窗或 `ConfirmButton`，不新增后端接口。分组的「清冷却」保持单击：它不删除业务数据，冷却会按运行时状态重新生成，加二次确认只会增加高频操作摩擦。
- Keys 列表原本已具备骨架、错误横幅与空态，源码不改；补充错误态回归测试。Groups 列表同样已具备三态，本次只补开关名称。

## 备选方案

- **保留保存按钮的 `disabled={!isValid}`，仅靠失焦显示错误**：按钮禁用时用户无法主动触发全量校验，空表单仍然只能逐字段发现错误。改为可点击提交后，错误一次性出现且请求不会发出。
- **给每个开关包一层 `<label>` 或统一 Field**：会改变现有卡片布局，且开关旁常是多行说明而非单一标签。`aria-label` 不引入视觉变化，也不与说明文本重复朗读。
- **把分组清冷却改成 `ConfirmButton`**：冷却不是数据删除，且现有测试与高频操作依赖单击语义；二次确认收益低于摩擦成本。
- **新增共享表单校验 hook 或 Form 组件**：本次只有两个弹窗需要 touched/submitted，抽公共层会提前引入未验证的抽象，违反 YAGNI。

## 后果

- **收益**：错误提示只在用户操作后出现；请求失败不再伪装成空数据；屏幕阅读器能区分不同开关与密码输入框。
- **代价与已知上限**：每个表单多一份 touched/submitted 状态，逻辑仍有局部重复。脱敏新增词的提交按钮仍在校验失败时禁用，因此「点击提交看全部错误」只能通过失焦触发。
- **未验证**：按仓库约定未执行 pnpm 构建、类型检查、测试或启动服务；本次仅做静态修改与断言补充，运行时行为需由用户验证。
