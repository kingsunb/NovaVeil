# Agent Note: 前端滚动跟随、表格可访问性与危险操作确认

Status: implemented

## 问题

控制台存在一组会直接打断操作或误导读屏的交互问题。对话页在每个 token 到达时强制平滑滚底，用户上翻阅读历史会被立刻拉回；日志页新请求顶插后阅读位置整体下移，而且表头与虚拟表体各自横向滚动，列宽对不上；错误日志行外层 `role="button"` 与内层按钮的 Enter 键同时触发，嵌套交互控件违反 ARIA；终止请求与批量清除单击即执行，移动端触点也小于 36px；Button 未声明默认 type，在表单内可能误触发提交；Field 用 `<label>` 包裹复合控件，点击标签会误触内部按钮；未选中开关轨道对比度不足，分段控件缺少键盘焦点环；错误边界与页面标题、主内容跳转也缺少统一语义。

## 决定

### 滚动与实时列表

- 对话页以距底 80px 为跟随阈值：滚动事件实时更新 `stickToBottomRef`，只有仍在阈值内才在消息变化时滚底。消息变化统一用 `behavior: "auto"` 一次到位，避免流式逐 token 与完整消息的平滑动画排队；也避免平滑过程连续触发 scroll、把跟随状态误判为「用户上翻」。离开底部后显示「回到底部」按钮，点击恢复跟随并立即滚底。
- 日志表头与虚拟表体放进同一个横向滚动容器：表头 `sticky top-0`，容器内层固定 `min-w-[1150px]`，行高保持 44px。虚拟器传入 `scrollMargin = headerHeight`，行位移改为 `translateY(vi.start - headerHeight)`，横向滚动不再需要两套容器同步。
- 新请求顶插只在 `scrollTop === 0` 时自动跟随；用户已经下翻时，按当前视口首行 id 重新定位并补偿行高差，同时累加锚点上方的新增条数，显示「有 N 条新请求」按钮，点击平滑回顶并清零。

### 交互语义与危险操作

- 错误日志行外层去掉 `role`、`tabIndex`、`onClick` 与键盘处理，只保留内层「展开/收起」按钮作为唯一交互入口。
- 终止请求与批量清除改为两段式：第一次点击进入待确认态并显示「确认终止」或「确认清除」，2.2 秒内再次点击才执行，超时自动复位。按钮在移动端保持 `min-h-9`（36px），桌面端恢复紧凑高度。
- Button 默认 `type="button"`，显式传入的 `type` 优先；`asChild` 模式不透传 type。
- Field 默认保持原有 `<label>` 包裹单控件的语义，新增显式 `group` 模式；复合控件传 `group` 后渲染 `div + role="group" + aria-labelledby`，不再把所有按钮和输入框包进 label。`htmlFor` 仍可用于显式关联单个输入。ContextProbe 的目标规模选择已改用 group 模式。

### 共享控件与布局

- 未选中开关轨道改为 `bg-ink/20 + border border-border`，选中态保留 `#30D158`；分段控件选项补 `focus-visible:ring-2` 焦点环。
- 错误边界的「↻」「!」文本图标替换为 lucide 的 `RefreshCw` 与 `AlertTriangle`。
- Topbar 页面标题由 `h2` 改为每页唯一的 `h1`；AppShell 增加「跳到主内容」skip link，main 设置 `id="main-content"` 与 `tabIndex={-1}`，路由切换后在布局阶段复位滚动并聚焦主区，首帧不抢焦点。

## 备选方案

- **距底严格为 0 才跟随**：滚动容器的高度变化或 1px 抖动都会立刻取消跟随，用户稍微回滚就失去流式输出；80px 阈值覆盖这类噪声，又不会在明显上翻后继续拉回。
- **完整消息也使用 smooth**：平滑滚动会连续触发 scroll 事件，此时距离仍大于 80px，跟随状态会被误判为用户上翻，按钮闪回；统一 auto 一次到位，避免初始加载、发送消息和流式输出三套时序互相干扰。
- **日志改成倒序列表或插入到底部**：能避免顶插位移，但会改变 SSE 顺序契约、现有测试与用户对「最新在顶」的预期；视口锚点补偿是局部改动。
- **表头单独横向滚动，用 JS 同步 scrollLeft**：需要额外监听与逐帧同步，滚动过程中仍可能出现一帧错位；单一滚动容器让浏览器原生保证对齐。
- **保留外层 role="button" 并阻止事件冒泡**：Enter 仍会在内外两层分别触发，且嵌套交互控件本身不合法；删除外层语义更直接。
- **复用 ConfirmButton**：现成组件只有 28px 高且不接受 className，无法满足移动端 36px 触点；扩展共享组件会超出本次范围，先用局部两段式状态，后续若确认交互统一再抽取。
- **Field 默认改为 div + aria-labelledby，并给单个子控件克隆 aria-labelledby**：能保持 `getByLabelText`，但需要判断子控件是否为容器，跨 69 处调用容易误判；默认保留 label、复合控件显式 opt-in 的回归面最小。
- **路由切换聚焦标题而不是主区**：标题不在每个页面都唯一且不一定可聚焦；主区是 skip link 的天然目标，聚焦 main 不改变标题语义。

## 后果

- **收益**：上翻阅读不再被打断；日志顶插与横向滚动保持阅读位置和列对齐；危险操作多一道确认，移动端触点达标；读屏只遇到一个交互入口，单输入 Field 的既有可访问名不变。
- **代价与已知上限**：日志锚点补偿以固定行高估算，遇到行高变化或运行中置顶重排只能近似保持；「有 N 条新请求」只在滚动到顶部时清零，用户停在半途会持续累加。两段式确认的超时复位逻辑在 Logs 与 ContextProbe 各有一份，后续可考虑抽成带 className 的共享组件。Field 的 group 模式需要调用方显式声明，其他页面的复合控件若未迁移仍保留旧的 label 包裹行为。
- **未验证**：按仓库约定未执行 pnpm 构建、类型检查、测试或启动服务；本次只做静态修改与测试断言补充，运行时行为需由用户执行下方命令验证。
