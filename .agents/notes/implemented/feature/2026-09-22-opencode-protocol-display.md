# Agent Note: OpenCode 模型协议只读展示

Status: implemented

## 问题

OpenCode 渠道的出站协议记在模型行 `upstream_protocol` 上，渠道类型表达不了同一模型在不同档上的协议。控制台若把空值显示成错误、0 或「不支持」，管理员会以为转发失败。协议也不是密钥；若照眼睛揭示密钥的做法另存一份，它就会离开渠道列表的 React Query 缓存。

## 决定

渠道编辑器只在 `opencode_compat === true` 的模型行上展示协议。`chat` / `responses` / `anthropic` 分别显示为 Chat、Responses、Anthropic。空字符串、字段缺失以及其他值（含 0）显示「按渠道」，表示按渠道类型转发，不用错误色。auto 与 manual 模型都只读，编辑器没有协议下拉，也不另做保存协议的表单。字段留在渠道模型上，随渠道列表进入 React Query，保存渠道时原样带在模型行里。其他渠道的模型行不渲染这段文案。

## 备选方案

- **给 manual 模型做协议下拉，并单独提交**：计划里 manual 可改，但写入路径还在和后端字段迁移对齐。只读展示能先看见已有值，又不会提前写死保存契约。
- **空值显示「不支持」或留空**：空值的语义是按渠道类型转发，不是失败。显示「不支持」会让人关掉本来能用的模型。
- **把协议放进与密钥相同的组件 state，避开 React Query**：协议不是明文密钥，列表响应里本来就有。再复制一份只会让展示和保存各看一处。

## 后果

- **收益**：OpenCode 渠道上能看出每个模型按哪种上游协议转发；空协议不会被看成故障。
- **代价与已知上限**：manual 模型不能在界面上改协议。后端开始接受写入后，要另做保存控件，并继续禁止非 OpenCode 渠道出现该控件。
