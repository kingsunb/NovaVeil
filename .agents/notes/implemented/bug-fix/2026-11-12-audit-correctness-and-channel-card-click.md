# Agent Note: 审计修复：JSON 感知还原、备份父行身份校验与渠道卡片点击

Status: implemented

## 问题

2026-11-12 全量审计确认三处行为缺陷。第一，非流式脱敏还原对整段响应做纯字符串替换，命中原文含引号、反斜杠或换行时会把合法 JSON 变成非法 JSON。第二，备份增量导入让渠道模型与分组成员按备份 ID 直接写入，父行因主键或自然键冲突被 `DO NOTHING` 跳过后，子行可能挂到本地同 ID 的其它渠道、模型或分组。第三，渠道网格与列表只有渠道名按钮和铅笔按钮能打开编辑器，点击卡片空白区没有反应。

审计同时复核了管理台的自定义头、头模板与代理地址显示。产品明确管理员后台可以看到所有信息，这是预期行为；本轮不新增敏感头名校验、不新增保存拦截，也不改变这些字段的明文返回策略。

## 决定

- 新增 `mask.RestoreJSONBytes`。映射表为空时原样返回；合法 JSON 按解码后的字符串值递归还原，再由 JSON 编码器写回，原文中的特殊字符自动转义；解码后没有占位符时直接返回原字节；非 JSON 输入回退 `RestoreBytes`，保留纯文本与二进制响应的既有行为。`restoreNonStream` 改用该入口。
- 备份预检按导入后实际可用的父行身份校验子行引用：渠道与分组使用 `ID + 名称`，渠道模型使用 `ID + (channel_id, 名称)`。本地同 ID 但名称不同、父行因自然键冲突无法写入，或分组成员的 `GroupID` 不存在时，子行引用写入 `InvalidRefs` 并拒绝整份导入；同 ID 同名称的父行继续复用。已存在 ID 的成员会被 `DO NOTHING` 跳过，不参与父引用校验；现存渠道模型只检查本地父渠道是否存在，不被 dump 中同 ID 异名渠道连带禁用。
- 渠道卡片点击空白区打开编辑。事件目标命中 `button`、`a`、`label`、`input`、`select`、`textarea`、`[contenteditable='true']`、`[role='switch']`、`[role='button']` 或 `[data-card-action]` 时不触发编辑，网格与列表共用同一行为；键盘入口继续使用渠道名按钮与编辑按钮，不给包含嵌套按钮的 `article` 增加 `role="button"`。
- 管理台自定义头、头模板与代理地址继续明文显示，不按“敏感头名”做额外打码或保存拦截。

## 备选方案

- **继续整段字符串替换还原**：实现最简，但原文含 JSON 元字符时会破坏响应结构；否掉。
- **只对响应的已知字段逐个还原**：能覆盖当前协议的主文本字段，但新增协议或嵌套字段容易漏；否掉，JSON 文档级递归更稳。
- **父行冲突跳过后继续导入子行**：保持“尽量多导入”，但会把数据挂到错误对象并静默污染路由；否掉，按仓库 fail-fast 规则整份拒绝。
- **先校验所有 dump 行再按 ID 跳过**：会把本应 `DO NOTHING` 的旧成员算作无效引用，导致整份导入失败；否掉，先按 ID 跳过再校验新行。
- **把管理台敏感字段打码**：能降低屏幕泄露面，但违背产品明确的管理员可见性边界；否掉。
- **给整张卡片加 `role="button"`**：可让卡片直接键盘触发，但与内部按钮形成嵌套交互语义；否掉，保留现有键盘入口。

## 后果

- **收益**：脱敏命中含引号、反斜杠或换行的原文时，非流式响应仍是合法 JSON；无占位符时保持原字节；备份导入不会把模型或分组成员挂到同 ID 的错误父对象，也不会因被跳过的旧成员阻塞整份导入；渠道卡片空白区可点击，网格与列表体验一致。
- **代价与已知上限**：只有解码后的字符串值含占位符时才重新编码，仍可能压缩空白或改变等价转义；JSON 键名不还原；非 JSON 响应仍使用整段替换。新增渠道 / 分组或新增模型身份有歧义时整份拒绝，需要管理员先处理冲突；现存模型不受 dump 中同 ID 异名渠道影响。卡片内未来新增的交互控件必须使用语义控件或 `data-card-action` 标记，否则会被当作空白区触发编辑。
