# Agent Note: 审计修复与明文密钥导出契约

Status: implemented

## 问题

2026-09-22 的代码审计把两类事情混在一起。渠道文本导出和数据库 JSON 导出里的渠道 Key、多 Key、API Key 明文是换机还原所需要的行为，不是缺陷。同一份导出里的代理、自定义头和请求头模板仍是 `****`，导入却会把它们密封成真实值，或因代理打码拒绝整份含明文 Key 的备份。

另外几处会在默认配置下产生错误行为：流式转发在正文传完前就记路由成功，提交后失败连击被清零，默认 3 次阈值下熔断不打开；custom 渠道可以先写入内网地址，再只改类型绕过出口校验；透传响应会带回 `X-Accel-Redirect`，非流式脱敏还原后仍沿用上游 `Content-Length`。

## 决定

- 渠道 Key 与 API Key 的明文导出保持不变。列表接口继续只出掩码。文档、变更日志和设置页写明这是预期行为。
- 导入遇到精确 `****` 的代理时清空该字段，丢掉打码的自定义头，并跳过整份都是打码头值的请求头模板。精确 `****` 的渠道 Key 与 API Key 仍然拒绝。
- 流式路由成功改到整段转发结束且没有失败哨兵之后再记。提交后进入冷却时拆掉该成员的亲和。请求取消不再把半开探测升档。释放探测占用时同时归还紧急并发额度。
- 从 custom 改成其他类型且请求没有新 BaseURL 时，复查库里的地址。模型同步在拉取前做同样的出口校验。6to4、NAT64、Teredo 内嵌的私网 IPv4 按内网拒绝。
- 透传丢掉 `X-Accel-Redirect`、`X-Sendfile`、`X-Accel-Buffering`，以及 `Connection` 点名的头。非流式正文长度与 `Content-Length` 不一致时删掉该头。自定义头不能写 Host、Content-Length、Transfer-Encoding、Connection，也不能从出站头回读 Authorization。
- 渠道编辑器点眼睛只在组件内展示明文，不写进保存草稿。登录限速按 IP 在单进程内串行化检查和记账。拉模型列表单次不超过 16MiB、32 页。用量金额的负值钳为 0。Debug 日志在级别不够时不再解析代理 URL。
- 初始密码文件在第一次登录成功时删除，不是改密之后。README 示例 API Key 改为占位符。

## 备选方案

- **把明文 Key 导出改回掩码**：能减少文件泄露面，但换机后不能直接还原调用。这是产品要保留的行为，所以只改文档和导入对非 Key 字段的处理。
- **每次拨号重新做 DNS 私网判断**：能挡住保存后的 DNS 重绑定。现行决定是保存时解析一次、之后不再改判，避免热路径和测试用回环地址被一起打断。这次不翻那个决定。
- **给流式响应加默认字节帽**：能限制内存，但图片、音频和长文本透传没有单独的安全上限，默认 0 仍表示不限。

## 后果

- **收益**：默认熔断能累计提交后的断流；导出的明文 Key 可以导入，打码的代理和头不会覆盖线上凭据；custom 改类型不能把内网地址变成可同步的上游。
- **代价与已知上限**：保存后 DNS 改指向内网仍然放行。多副本登录限速仍可能并行插入失败行。流式响应默认仍不限制总字节。自更新仍只核同一 Release 上的 SHA256SUMS，且默认关闭。

## 验证

- `internal/op/channel_url_test.go` 拒绝 6to4、NAT64、Teredo 内嵌私网地址。
- `internal/op/backup_import_test.go` 拒绝打码 Key，并断言打码代理和自定义头被丢掉、明文 Key 仍导入。
- `internal/relay/header_copy_test.go` 断言 `X-Accel-Redirect` 与 `Connection` 点名的头被丢弃。
