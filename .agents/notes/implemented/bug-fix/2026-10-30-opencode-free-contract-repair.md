# Agent Note: OpenCode 免费档保留客户端契约并隔离每轮还原

Status: implemented

## 问题

静态审查发现免费档整形把 Chat、Responses 和 Anthropic 混为一条分支，原生工具可能被替换为 Chat 工具。客户端同名 `patch(diff)` 被改成官方 `patch(patchText)`，响应只还原名字，无法保证客户端能执行。跨协议发送丢弃工具别名表，同协议流式 HTTP 错误又丢弃响应头，导致 `Retry-After` 无法传到冷却逻辑。

身份替换原实现把 `opencode` 替换为自身，测试同时要求结果包含和不包含同一字符串。用户确认保留实际替换，但只限 OpenCode 免费档的系统提示词，不改用户消息、历史回答、工具参数或其它正文；不同原名可以使用独立别名。多个名字统一成一个词无法可靠逆向还原。

Bun 启动失败被永久缓存；本地 HTTP 请求虽携带 Go Context，上游 fetch 未显式绑定取消信号；正文传输还额外创建 base64 字符串及重复字节数组。

## 决定

### 协议、工具与转换边界

- [免费档整形](../../../../internal/relay/opencode_free.go) 按出站协议分别处理。Chat 两档复用仓库现有官方模板；完整定义语义一致的工具复用，冲突客户端工具保留原始定义，只改出站名并同步指定工具选择与历史调用引用。v1 的 Responses/Anthropic 保留原生工具，不引入 Chat 的 read 或全集模板；v2 原生协议只补缺失核心工具，不覆盖客户端同名 schema（即：参数结构约束）。Responses 两档补齐 instructions。
- 摘要命名仍为 `clint_` 加 SHA-256 前 12 位十六进制，已有摘要及冲突后缀不二次摘要。预占原始工具名避免冲突；映射只存当前尝试的本地状态，不写入出站正文，不使用全局缓存。二次整形无新增映射时返回空表，调用方须保留首次映射。
- [转发链](../../../../internal/relay/upstream.go) 在跨协议响应进入转换器之前还原结构化工具名称，覆盖非流式、流式窗口和余流；不替换参数或普通文字。免费档指定工具选择不能被通用 Chat 字段过滤丢掉。提示缓存键在免费档整形前回写，避免绕过 v1 的字段剥离。
- Responses 转换库的工具参数 schema 使用 `map[string]any`，普通 JSON 解码会把 `9007199254740993` 变成不精确的浮点数。免费档转换前保存各工具 schema 的原始 JSON，转换后按名称及同名出现顺序回填，然后再应用渠道显式参数覆盖；不修改依赖包，不改变非免费渠道。调用参数仍走已有的原始 JSON/字符串通道。

本决定取代 [v2 免费档整形](../feature/2026-10-21-opencode-v2-free-tier-shaping.md) 与 [工具别名和天锚](../feature/2026-10-25-opencode-v2-tool-alias-and-day-anchor.md) 中“覆盖客户端同名工具 schema”的部分；会话、头与日期锚决定不变。[摘要工具名](./2026-10-30-opencode-tool-name-digest.md) 的命名决定不变，仅同步幂等事实。

### 系统提示词身份别名

- [身份模块](../../../../internal/relay/opencode_alias.go) 仅处理 Chat 的 system/developer 文本、Anthropic 顶层 system 文本块、Responses instructions 及 system/developer 输入文本块。ASCII 字母、数字、下划线边界内的复合标识不匹配，中文邻接可匹配。
- 大小写不敏感匹配 `deepseek HARNESS`、`opencode`、`grok build`、`liveagent`、`novaveilagent`、`workbuddy`、`zcode`；每个实际原始拼写派生稳定的 `opencode_` 摘要别名，并检查整份原始 JSON（含解码后字符串）的冲突。每轮独立保存精确原文映射，普通 `opencode` 回答文字和未登记的摘要保持原样。
- 替换在实际免费档发送入口进行，不在全局 handler 改请求。跨协议先复制请求结构，再按入站协议处理提示词，之后才交给转换器，避免开发者消息角色归一化后丢失作用范围；重试仍使用原始请求体。
- 响应仅还原文本与推理字段，不修改工具参数。流式按 choice、块或输出项隔离，只保留潜在别名尾缀，窗口与余流共用状态。终止或错误事件前补出尾缀；提前 EOF 不伪造终止帧；读取、关闭和还原错误保留。待决通道上限 256、精简事件模板上限 16 KiB，超限报错。Responses 源流带序号时，所有输出包括补帧从首序号连续编号。

### HTTP 错误与 Bun 生命周期

- 同协议流式失败保留状态、响应头、有限正文以及读取/关闭错误；[错误分类](../../../../internal/relay/state.go) 遇到明确非零 HTTP 状态优先按状态分类，不因错误正文截断降为网络故障。只修传递链，不更改秒数 `Retry-After` 优先、UTC 零点回退、24 小时上限的[冷却决定](./2026-10-26-opencode-429-retry-after-cooldown.md)。
- Bun 保留单进程、串行启动和 JSON/base64 本地协议。启动失败冷却 1 秒，后续请求按需重试启动，成功清空失败状态，不自动重放业务请求。fetch 绑定 `req.signal`，保留 `idleTimeout: 0`。Go 正文改为 `[]byte` 由 JSON 编码，Bun 直接使用 Buffer，减少中间复制。同步既有 [sidecar 决定](./2026-10-26-opencode-bun-sidecar-tls-behavior.md) 与[空闲超时笔记](./2026-10-28-bun-sidecar-idle-timeout.md)，不另换传输协议。

## 备选方案

- **继续用官方 schema 覆盖客户端定义，再在响应侧改回名字**：工具参数语义已经改变，只还原名字无法补救；本次不凭空编造 `patchText` 与 `diff` 的通用转换器。
- **所有协议套 Chat 模板**：原生 Responses/Anthropic 结构不同，无法以同一字段路径安全合并；按协议分流且不新增未经取证的 v1 原生工具注入。
- **移除身份功能或所有名字统一成 opencode**：用户选择保留功能；多对一映射无法区分回显与普通文字。独立稳定摘要兼顾精确还原与跨请求提示前缀稳定。
- **复用脱敏引擎还原身份别名**：既有引擎绑定 `{{...}}` 占位符与私有映射，已有事件处理还涉及工具参数，超出本次文本白名单。使用身份模块内的有界流包装，不修改脱敏模块。
- **本次改成二进制 sidecar 协议或无限启动重试**：前者扩大线格式变更面，后者可能放大故障与重复业务请求。保留 JSON/base64，只移除明确冗余复制并让后续请求受控重启。

## 后果

- 收益：客户端工具名称与参数约束成对保留，原生协议不被 Chat 工具污染；同协议与转换链都持有每轮映射；流式限流头可到达账号冷却；短暂 Bun 启动故障不再要求网关永久重启。
- 代价：响应文本还原增加每通道的小尾缀状态，必要时生成最小增量帧；映射只在当前请求有效，不能跨请求替其它请求还原。保留客户端 schema 可能改变上游观察到的工具形态，仍需实际官方客户端对照验证。
- 仍有成本：本地 HTTP、完整请求缓冲及 base64 约 4/3 线体积未消除。本次没有性能实测，不宣称吞吐、内存或延迟提升比例。
- 边界：官方工具模板、UA/TLS 版本、代理池策略、服务器部署均未修改。本次只证明代码内契约，未重抓最新官方客户端；不能把后续 429 直接归结为额度，也不能宣称形态已完全对齐。

## 验证

新增或更新测试覆盖两档三协议、同名工具参数与大整数、工具引用和返回名、身份作用范围与逐字节分片、每轮隔离、错误头与截断诊断、Bun 并发首启/启动恢复/取消/二进制正文，以及经 `sendPassthrough` / `sendConverted` 的真实转发链契约。测试与编译未由 AI 执行，真实 Bun 取消传播、性能和服务器行为尚无本轮运行证据。

由用户在项目根目录执行：

```sh
go test ./internal/relay ./internal/client -count=1
go build ./...
pnpm verify-notes
```

Bun 进程级测试要求配置 `NOVEIL_BUN_BIN` 或 `BUN_BIN` 为真实可执行文件；未配置时会跳过，不能把跳过当取消传播已验证。完整验收还需要用户回报执行结果。
