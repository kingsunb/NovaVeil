# Agent Note: OpenCode 免费档 403 时直接换代理账号重试

Status: implemented

## 问题

OpenCode 免费档的代理账号只是出口 IP。上游返回 403 表示当前出口被标记，换一个账号即可继续；这不表示承载请求的分组成员、渠道或其他代理账号不可用。

旧实现已经会在 403 时冷却当前账号，但请求随后仍落入成员级失败处理。按默认 `MemberMaxAttempts=3` 时，同一个坏出口会在同一成员上重复三次，达到阈值后整个成员进入冷却并被排除；同一请求不会立即换账号。结果是单 IP 的预期封锁被放大成渠道级故障，免费档的账号池失去意义。

账号池本身的选号、冷却、成功复用与落库规则见 [按出口 IP 轮换代理账号池](../feature/2026-10-20-opencode-free-proxy-ip-pool.md)。

## 决定

业务请求在满足以下全部条件时，在同一成员上换代理账号重试：

- 上游状态码为 403；
- 本轮确实使用了账号池选出的代理账号（`proxyAccount != ""`）；
- 当前成员本请求已换号次数小于 `ocProxyMaxRetries`。

处理顺序固定为：先由 `markOpencodeProxyForbidden` 冷却当前账号，再用 `finishRound` 把本轮记为 4xx 失败，释放轮次生命周期，归还引用链探测占用，然后 `continue` 重新选路。重试不调用 `recordRouteFailure`，不设置 `exclude`，不清会话粘合，也不写成员冷却或半开标记。

`ocProxyMaxRetries` 固定为 3，不新增配置项。每个成员每请求最多换号 3 次，即最多覆盖 4 个账号；计数按成员存放在请求级 `map[int]int` 中。账号池全部冷却或并发满时 `pickOpencodeProxyAccount` 仍可能新建账号，但新建同样受该上限约束。耗尽时把最后一个账号固定在请求内，后续成员级失败重试不再调用账号池；只有成员失败计数达到阈值、切换到其他成员或请求终止才会结束，因此上游尝试总数仍由既有成员重试策略决定，但不会继续新建账号。

403 发生在首个有效事件之前，此时 `result` 尚未提交给客户端；换号路径沿用既有失败收尾，不写出任何响应字节，因此流式与非流式请求都不会泄漏已打开的响应流。`context_probe.go` 的单发容量探测不换号，本次不改其语义。

429 复用同一套换号预算，但账号冷却时长改为 24 小时，见 [OpenCode 免费档 429 冷却代理账号 24 小时并换号](2026-10-22-opencode-429-account-cooldown.md)。

多 Key 渠道中 403 与 Key 轮换分支的优先级修正见 [多 Key OpenCode 渠道 403 不冷却 Key](2026-10-22-opencode-403-multikey-priority.md)。

## 备选方案

- **保持成员级失败处理** — 改动最小，但一个坏出口会重复击打同一成员并把整条渠道冷却，正是本次要修的问题。
- **为 OpenCode 增加 lane 级暂停、熔断或单飞（single-flight）** — 能阻止坏 IP 继续消耗，但账号只是出口，成员级已有三态熔断与多成员路由；再叠一层 lane 状态会让一次 403 同时污染账号、成员和渠道三层，且需要新的恢复语义。
- **达到上限后继续无限换号** — 用户成功体验最好，但每次换号都会生成新账号与代理客户端，坏代理或上游持续封锁时可无限放大请求与连接资源。
- **直接复用容量探测路径完成换号重试** — 探测是单发诊断，不承载完整业务请求与流式响应生命周期；复用会把探测语义和业务失败记账混在一起。

## 后果

- **收益**：单个出口 IP 被 403 后，同一请求最多再试 3 个账号即可恢复；成员健康度、会话粘合与其他渠道不会被单 IP 封锁污染。
- **代价与已知上限**：单成员单请求会先覆盖最多 4 个账号，坏出口场景的延迟与代理流量相应增加；预算耗尽后仍按既有成员重试策略复用最后账号，直到成员冷却或换渠道。重访信号：上游开始对账号做长期封禁并需要跨请求共享失败历史，或代理供应商的账号创建成本显著上升。
