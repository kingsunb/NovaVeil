# Agent Note: 渠道测试按生效协议模拟下游并保留完整状态生命周期

Status: implemented

## 问题

渠道编辑器常驻挂载，切换目标或关闭时设置共享的中止布尔值，只有批量测试会复位。重新打开后单模型测试仍向上游发请求，但成功与失败响应都会被前端丢弃。新批次复位这个布尔值又会允许旧请求回写，旧请求的 finally 还可能清掉新请求的加载状态。

测试后端只在单模型和分组请求结束后创建日志行，逐密钥测试没有日志；运行期间无法观察请求或停止它。终态登记没有进入完成队列，也不能按日志历史上限淘汰。固定 Chat 入站不能表达用户要求的“渠道是 Chat / Responses / Anthropic，测试就模拟同协议下游”。原生回复的推理块可能排在正文前，只读取第一个内容块会漏掉回答。

## 决定

`internal/relay/test.go` 用 `testRequestTarget` 按 `outboundProvider(channel, channelModel)` 选择模拟的下游格式，渠道模型从已保存模型列表按名称定位。普通渠道按类型，OpenCode 兼容渠道遵循模型协议覆盖，完全透传仍优先于模型覆盖。Chat、Responses、Anthropic 分别构造 messages、input、messages 报文；`newTestRequest` 同时填写对应 `/v1/*` 入站路径，Anthropic 携带协议版本头。Gemini、Volcengine、自定义固定回复没有网关原生入站，使用 Chat 并复用既有转换器。

单模型、逐密钥、分组和评估使用 `sendTestRequest`，复用真实转发的出站构造、透传或转换、密钥凭据、代理、参数覆盖、模型限制和动态请求头。诊断指定渠道，不引入分组选路或修改冷却状态；面板输出上限 4096，评估上限 100000，逐密钥和分组成员独立超时 60 秒。

`startTestRequest` 在上游调用前登记 running 状态；每次基础设施重试调用 `startRound` / `finishRound`，在同一请求内保留真实尝试次数。`finishTestRequest` 更新同一个 ID 的成功、失败或取消终态，失败进入最近失败摘要，所有终态进入有界完成队列。密钥、代理或转换器准备失败也登记失败结果。日志的停止操作取消探针上下文，等待重试时也能退出。请求和响应正文通过既有按需接口查看，内存预览保持 64 KiB 上限，HTTP 错误正文在可取得时保留。

探针仍以“面板测试”标记来源，不计入业务客户端计数、用量分桶和对话留存。运行中计数和日志展示来自相同请求状态表。

编辑器以递增代次区分编辑会话和所选密钥，以单模型请求票据区分同一模型的并发请求。过期的成功、错误、finally 和批量队列均不能影响当前会话。关闭不撤销已发出的请求，日志仍跟踪其结束；尚未派发的批量项停止发送。列表、编辑器和逐密钥入口共用 `useChannelTestMessage`，从设置读取消息并回退到默认测试问题。回复提取遍历 Anthropic 文本块和 Responses 的 message 文本块；成功但无文本时显示 locale 中的明确说明。

- 活跃树没有 proposed / rejected 目录，没有待处理的同主题提案；没有完全吸收或需要归档的笔记。

## 备选方案

- 仅在单模型测试开始时把共享中止布尔值复位：可以修复最直观的结果丢失，但会重新放行旧请求和旧批次，无法隔离关闭后重开同一渠道的请求，所以使用代次和票据。
- 保持固定 Chat 或增加前端协议选择器：固定 Chat 能检测 Chat 到其他上游的转换，选择器能覆盖多种入站；用户要求按渠道类型自动测试，因此按已保存的生效协议推导，避免引入额外选择步骤。需要验证跨协议客户端时应另行覆盖真实入站请求。
- 直接使用业务 `newRequestState` 与 `markSucceeded` / `markFailed`：能复用完整记账，但会把管理诊断计入客户端统计、用量与对话留存。探针只共用状态表、轮次和发布机制，保留原有统计边界。

## 后果

测试结果不会因共享中止标记被静默丢弃，原生协议回复中的正文可以完整提取，诊断从发起到结束可在日志观察和停止。共用发送函数减少单模型、逐密钥和分组之间的协议、动态头和日志差异。

日志增加每把密钥的运行态、尝试轨迹和终态事件，仍受既有 SSE 缓冲与历史保留上限约束；密钥很多时会挤出更早的终态日志。单模型测试证明的是对应生效入站协议的可用性，不能代表所有跨协议转换、分组选路和流式场景。缺少真实渠道或模型参数的管理 API 校验失败仍由管理接口返回，不伪造上游请求。

## 验证

回归源码覆盖编辑器首次打开与重开后的成功/失败、旧请求与旧批次隔离、密钥切换、自定义测试消息、空文本提示；后端覆盖原生报文与路径、Anthropic 版本/认证头、OpenCode 模型协议和完全透传优先级、运行态到终态的同 ID 更新、人工停止、准备失败、回复文本块提取和代理标记。

本次续接验证中，`go test ./internal/relay` 通过；前端 `pnpm typecheck`、`pnpm lint` 和 `pnpm test` 通过（53 个文件、575 项测试）。类型检查发现并修正回归测试中 `getByRole` 不支持的 `exact` 参数，字符串名称匹配本身已是精确匹配。前端全量测试输出包含访问本地 3000 端口被拒绝的日志，但所有断言通过。

用户随后要求不要本地编译运行，后续仅做静态核对和提交。停止检查时前端验证已结束；Agent Note 门禁只确认树结构及相对链接通过，格式和归档封印未取得完成结果。没有启动应用服务，没有执行后端全量测试或构建；这些检查仍需 CI 验证。
