# Agent Note: 脱敏占位符明确标记类型并排除版本号误判

Status: implemented

## 问题

短标签和标签截断会让模型难以理解占位符代表什么；公网 IPv4 的点分数字形状与四段版本号相同，缺少上下文边界时可能误脱敏。JSON 请求体只把解码后的字符串值交给规则引擎，键名上下文丢失，键为 `version` 的四段值无法与真实 IP 区分。规则配置标签同时承担稳定开关 ID，不能随显示名变化而迁移配置。

## 决定

新生成的占位符采用 `{{REDACTED_<完整类型名>_<6位辅音>}}`。`REDACTED_` 明确表示原值已被网关脱敏；内置类型名保留完整单词与下划线；未知扩展标签按长度上限裁剪。旧 `{{LABEL_辅音}}` 格式继续被占位符识别器接受，用于多轮输入跳过及响应还原。规则开关 ID 和命中明细 label 保持原值，不随占位符标签改名。

短规则标签映射为更明确的内容类型，例如 `CONNSTR` → `CONNECTION_PASSWORD`、`TOKEN` → `BEARER_TOKEN`、`IP` → `PUBLIC_IPV4_ADDRESS`、`TERM` → `CUSTOM_SENSITIVE_TEXT`。超长类型名按固定上限裁剪，令占位符总长度不超过现有命中明细边界。

公网 IPv4 候选检查完整字母数字/点号边界；尾部单个句点在后面没有字母、数字、下划线或点号时作为标点保留。额外数字段与域名式后缀不截半脱敏。候选只在行内前缀紧邻版本标记时排除。已知版本上下文包括常见版本关键词、中文版本词、浏览器名称；关键词与分隔符两侧允许单双引号。此检查以候选为单位，不因同一行其他位置出现版本词而跳过真实 IP；公网地址范围校验保持不变。

版本上下文只读取候选前最多 96 字节，再在此窗口内寻找换行。窗口触及字符串开头且没有换行时，按剩余容量拼接 JSON 对象键名的尾部，键为 `version` 的四段点分值同样按版本号保留。每个候选的上下文扫描和拼接都有固定上限，长行中的后续候选不会反复扫描整段前缀。

## 备选方案

- **只保留原短标签并补提示词** — 最强理由是占位符格式不变；但用户希望从占位符自身辨认语义，且提示词会受客户端协议和指令拼接位置影响。
- **整行出现版本词就跳过 IP 检测** — 实现简单；但会让同一行内真正的公网地址漏出，故只检查紧邻候选的上下文。
- **改规则 ID 以匹配显示类型名** — 命名一致；但会造成已有开关配置失配，因此配置 ID 与显示标签分离。
- **预先索引全部换行再二分查找** — 能准确定位任意候选所在行；但版本匹配最多读取 96 字节，窗口外换行与键名均不影响结果，额外索引和查找没有必要。

## 后果

- **收益**：模型更容易理解凭据、地址和自定义文本占位符；内置长规则标签不再因旧 12 字符上限被截断；常见版本号不再仅因四段点分数字形状被识别为 IP；旧占位符可继续往返还原。
- **代价与边界**：缺少版本上下文的四段公网数字串仍无法仅凭文本区分 IP 与版本，继续按公网 IP 保护；上下文词表是有限集合，新增客户端版本形态时需补规则与回归用例。版本标记超过 96 字节窗口时不参与判断；这维持有界成本，也可能使极长分隔空白后的四段版本值按公网地址保护。
