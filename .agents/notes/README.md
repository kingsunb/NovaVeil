# Agent Notes

NovaVeil 的工程决策记录。一篇 **Agent Note** 记录影响本仓库的一个决策或提案——*为什么这么做、放弃了什么*，代码和 docs 装不下的那部分。本文件定义笔记放哪、何时写、[文件格式](#文件格式)。

> 与 `docs/` 的分工：`docs/` 描述「当前系统怎么运转」（事实）；`.agents/notes/` 记录「当初为什么这么定、否过什么」（因果）。两者物理隔离，职责不混。

## 路径即分类

每篇笔记的路径就是身份：`{lifecycle}/{class}/yyyy-mm-dd-topic.md`

**Lifecycle**（一层文件夹，笔记走到哪一步）：

- `proposed/` — 提案阶段，有方案但未落地
- `implemented/` — 已落地，与代码同批改动保持同步
- `rejected/` — 审慎否掉的提案，仅当能防止重犯时保留，否则删整组
- `archived/` — 已完成且未来参考价值低的 implemented 记录，**冻结不可改**

**Class**（二层文件夹，闭集 6 个；再加要改 `scripts/agent-notes/agent-note-tree.ts`）：

| Class | 覆盖 |
|---|---|
| `feature` | 新的用户/模型可见能力 |
| `bug-fix` | 修缺陷或补 postmortem 暴露的缺口 |
| `simplification` | 删代码/行为/暴露面，不加能力 |
| `architecture` | 关于** shipped 源码**的结构决策——包怎么组织、运行时词汇 |
| `process` | 代码**周围**的工具/流程——CI、脚本、发布 |
| `testing` | 测试基建与策略 |

`architecture` vs `process`：architecture 是我们 ship 的源码；process 是周边工具链。`refactor` 故意缺席——它被 `simplification` 覆盖（判别式：可观测行为变了吗？）。

文件名日期是**首次提出日**（按 git 历史）。跨笔记引用用相对 markdown 链接（`[topic](../../implemented/architecture/2026-…-….md)`），不用裸数字，便于机械校验且能在移动文件夹后存活。

**禁止维护全局 `INDEX.md`**：多分支并行时总索引会产生提交冲突。按 lifecycle/class 文件夹浏览或全仓搜索即可。

## 何时写

每个**非平凡改动**必须在同一 PR 里新增或更新至少一篇 Agent Note。非平凡 = 改了**行为**、**架构**、**跨文件契约**、**流程/工具链**、**测试策略**、**落盘/网络/配置格式**，或其他维护者日后可能重访的决定。已有归属的改动直接更新那篇，不新建重复。

纯机械或局部编辑免除：排版格式化、错别字、无歧义重命名、样式调整（不改行为）、依赖补丁、版本打标、常规 CRUD、看 diff 即懂的单模块显式修复。

> 一句话：**代码和单测说不出来的意图、边界、取舍，就是非平凡。** 判不准时，从严。

## 原地同步，非必要不新建

DeepSeek 的演进历史里，Note 变更大头是**就地修改现有 Note 的事实**（路径、类名、默认参数），而非开新文件。重构/改名/改默认值时，直接在正文中替换旧值——**不追加变更流水账**，保证任何时候打开这篇 Note 反映的都是 HEAD 的绝对事实。时态永保现在时（`系统使用 SQLite`），严禁变更叙事（`系统不再用 JSONL，现在用 SQLite`）。

**禁止把一篇 Note 改写成另一个决定**：事实就地改；决定或理由翻转 → 新开一篇并互链。禁止把 `## 决定` 改写成反面，禁止只靠 git 当旧理由的唯一副本。

## 取代与归档

- **部分取代**：新方案只覆盖旧方案一部分 → 两篇都留、互链，只更新仍成立的事实。禁止归档。
- **完全吸收**：旧方案被彻底淘汰 → 把旧篇独有内容（安全边界、否定性保证、重新引入条件）吸收进新篇，再二选一：新篇已写入全部独特内容且入站链接改完 → 物理删除；旧篇还有独立杠杆 → 用 `pnpm archive-agent-note` 归档。指针写在新笔记，不写进归档篇。
- **归档即冻结**：归档后只插 `Archived: YYYY-MM-DD` 一行，永不再编辑、移动、删除，不当作当前行为的权威。文档门禁跳过归档源。

## 文件格式

每篇在役笔记遵循同一格式，由 `pnpm verify-agent-note-format`（`scripts/agent-notes/verify-agent-note-format.ts`）强制。模板见 [.agents/skills/write-notes-like-deepseek/templates/](../skills/write-notes-like-deepseek/templates/)。

### 头块（前三行）

```markdown
# Agent Note: <标题>

Status: <状态>
```

`Status:` 取值三选一，且必须与所在 lifecycle 文件夹一致（脚本交叉核对）：

- `Status: proposed`
- `Status: implemented`
- `Status: rejected — <一句话原因>`

状态不含日期与括号；文件名存首次提出日，git 存其余时间。头块 `Agent Note:` 与 `Status:` 保持英文原文以便脚本核对，正文用中文。

### 正文骨架

每篇以 `## 问题` 开头——动机要能脱离方案独立成立。之后按 lifecycle 区分：

**`implemented/`**

```markdown
## 问题
## 决定
…自由节（包拓扑/契约/schema 等）…
## 备选方案
## 后果
```

`## 决定` 用现在时描述已落地事实；门禁拒绝提案态标题（`## 提议`/`## 方案`/`## 计划`/`## 验收标准` 及英文别名）；`## 后果` 同时记代价与收益；可按需加 `## 验证`/`## 测试` 等现在时事实节。

**`proposed/`**

```markdown
## 问题
## 提议
…自由节…
## 备选方案
## 验收标准
## 风险
```

**`rejected/`**：冻结的提案形态，verdict 在 `Status:` 行，保留提案时的节，不改写为对立面。

### 备选方案（必写）

每篇必含 `## 备选方案`：每个**真考虑过**的备选为何没选，一段一备选（或 `### 为什么不选 <X>?` 子节）。**没考虑过的选项不要编。**「不做/复用现状」仅当当时真的权衡过才写。脚本只查这一节在不在——但缺了它，下个会话的 Agent 会把否掉的方案当新点子再提一遍，这正是笔记要防的。

## 校验

```sh
pnpm verify-notes          # 树结构 + 格式 + 归档封印，CI 也跑
pnpm check-anchors         # 软报告：源码反向注释指向的笔记是否还在（不进 CI）
```

写新笔记前先搜 `proposed` + `implemented` + `rejected`，当场分类取代关系，和新笔记一起落盘。
