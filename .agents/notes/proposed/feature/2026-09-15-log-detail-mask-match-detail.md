# Agent Note: 日志详情展示脱敏命中明细（规则/原文/占位符）

Status: proposed

## 问题

日志页已显示"已脱敏"标记与占位符，但详情中看不到"哪个内容触发了哪条脱敏规则"，规则调优与审计只能靠猜。脱敏引擎 `internal/relay/mask/engine.go` 的 `Apply` 已返回结构化 `MaskResult.Matches`（label/original/placeholder），但转发入口 `applyRequestMask` 只用了 `Masked` 与 `Mapping`，命中明细被丢弃。需求不改变请求转发和响应还原逻辑。属于网关层脱敏的后续增强，总决策见 [网关层脱敏](../../implemented/feature/2026-09-10-gateway-native-request-masking.md)。

## 提议

把引擎已产出的命中明细接通到日志详情：

1. 扩展 `applyRequestMask` 返回 `[]mask.Match`（开关关闭/未命中时返回空明细，零额外展示数据）。
2. `RequestState` 增加仅在脱敏发生时输出的 `mask_matches` 字段，元素形状复用现有 `/api/v1/mask/test` 的 `maskTestMatch`。
3. `handler.go` 应用脱敏后把命中明细复制到 `request.MaskMatches` 并发布请求状态，使已打开的日志详情实时收到。
4. 前端 `TraceSheet` 在请求体面板内增加"脱敏命中"区：每条一行（规则标签 Pill + 占位符 + 原文），原文默认视觉弱化需点击展开，无命中不渲染。
5. 持久化错误日志（可选）：`model.ErrorLog` 增加 `MaskMatches` TEXT 字段，旧记录空数组天然兼容无需迁移；命中明细保留策略与完整请求体配额（每类前 3 条）对齐。

不变项：不把原始请求体写回 body、不改发往上游内容、不新增明文恢复接口、跨轮占位符复用与 `StreamRestorer` 逻辑全部现状保留。详细方案见 [docs/脱敏开发/07-日志详情命中明细.md](../../../docs/脱敏开发/07-日志详情命中明细.md)。

## 备选方案

- **不做，只看占位符** — 最强论据是零改动、不碰凭据红线；否掉因为无法定位"哪个内容触发哪条规则"，规则误报调优与审计只能靠猜，脱敏功能上线后这恰是管理员最需要的能力。
- **新增请求体明文恢复接口** — 最强论据是信息最全；否掉因为扩大攻击面，违反"日志只存脱敏后内容"的凭据红线，命中明细随状态流下发已足够且不新增明文接口。
- **命中明细落对话留存/默认落盘原文** — 最强论据是审计可回溯；否掉因为命中原文是敏感数据，落盘扩大暴露面。改为仅管理员面可见、前端默认弱化、错误日志可只存 `label + placeholder` 不存原文。

## 验收标准

- 命中 PHONE + 自定义 TERM 后，`RequestState` JSON 含正确的 label/original/placeholder；无命中与开关关闭时无该字段或为空数组。
- 发脱敏请求后状态流的 `mask_matches` 与请求体中的占位符一致；转发上游 body 与响应还原不受影响。
- 旧记录无字段可正常读取（前端与反序列化按可选处理）；命中明细不突破请求体配额策略。
- 前端无命中时不渲染"脱敏命中"区；原文默认弱化，管理员可展开。

## 风险

- **敏感原文重新可见**：命中明细含原文，与"日志只存脱敏后内容"红线有张力。对策：仅管理员面可见、错误日志可只存 label+placeholder、前端默认弱化展示。
- **SSE 载荷增大**：命中明细通常几十条以内体积可控；进程内状态终态后按 `maxFinished`（200）裁剪。
- **旧版本进程/旧记录兼容**：字段缺省为空，前端与反序列化均按可选处理，天然兼容。
